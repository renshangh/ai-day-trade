# C 入场原理与六个案例的 P1 旁路对照

对照已保存的 C 买点，不改变规则、不重新运行整月交易。

Last Updated: 2026-11-09
Status: Read-only six-case comparison; not an approved C filter
Audience: 交易桌使用者和研究维护者

## Overview

**父 D 的 P1 检查六例全过；近端 HL 的 P1 检查只让 #13 通过。**
因此假设把后者作为 C 的额外门槛，会拦住五笔亏损中的四个原始入场，
也会错过 11/09 03:17。它增加确认，却没有解决父/子波段归属；不能把这六例
理解成已经改善整月收益。本次没有新入场、延迟入场、替代成交或新 P/L。

## C 的实际原则

C 是大父底后的较早延续试探，不要求 A 的四个独立 LL：

1. 找到已完成确认、此后未跌破的小时父 D。
2. 父 D 后已经有确认反弹峰，再找确认的十五分钟回踩低点 HL；其价格需高于
   父 D 加原 0.1 入场 ATR 容差。HL 用完整左右邻居 K 线确认，outside turn 不猜顺序。
3. 盘中越过前一根完整十五分钟 K 线最高价加 $0.01，可形成 C 价格信号，
   不必等当前根收盘，也不必突破整个大峰。
4. 原初始止损仍为大父 D 减 0.25 入场 ATR；原目标、25%/余量退出、成本、
   追价上限与其他风险检查不变，2R 仍仅供参考。
5. A/B 同分钟有优先权；持仓不叠加 C；第一次穿越消耗该 HL 机会。

目前 C 的缺口是：价格高于某个完整旧 D，不自动证明两者属于同一级别波段。
P1 也不是波段树，不负责判断更旧 D 是否已被后来的波段接替。

## 对照范围：两个低点，不能混为一个检查

P1 原用于 A 的独立 LL。这里只是把原 `P1Detector.low_check()` 分别用于：

- **父 D**：检查旧大底本身当初是否得到充分反弹确认。
- **近端 HL**：把这个入场回踩低点当作待确认低点，检查原买入时是否已经
  有足够后续 K 线。这是旁路假设，没有接入 C，也没有要求 C 形成四个 LL。

三个原条件：至少两根连续、完整、低点严格高于待测低点的十五分钟 K 线；
完成 K 线的反弹高至少达到低点 + 1 ATR；完成收盘至少一次达到低点 + 0.5 ATR。
这里 ATR 使用待测低点所在 K 线之前的十四个完整真实波幅，不是入场 ATR。
若先跌破待测低点或缺失确认观察，原检查不会假定成功。已合格的历史低点
保持合格，不会因更晚的下跌倒改历史。

## 为什么 03:17 会被挡住

近端低点是 02:58 的 **73,629.551**。该点之前 ATR 为 **283.1292**，
所以完成反弹高需达到 **73,912.6802**，完成收盘需达到 **73,771.1156**。

03:17 当时只能使用已完成的 03:00–03:15：

- 低 **73,641.1125**，守住低点，但只有一根。
- 高 **73,866.995**，还未到 73,912.6802。
- 收 **73,790.385**，0.5 ATR 收盘条件已满足。

之后的 03:15–03:30 真正完成时，累计完成反弹高达 **74,164.80**，最佳完成
收盘 **74,084.23**，两根守底及距离才全部合格。这是 **03:30 才知道** 的信息，
不可提前用于 03:17。没有用该完成价虚构新买单或重新计算整笔收益。

## 为什么 #13 仍会漏过

20:52 的 81,301.363 之后：

- 21:00–21:15 低 81,559.91、高 81,820.85、收 81,619.635。
- 21:15–21:30 低 81,387.505、高 81,706.092、收 81,477.10。

两根都守住低点；ATR=192.2030，所需高 81,493.5660、所需收 81,397.4645，
已经满足。21:30 P1 合格，21:32 原买点仍会通过。但它仍沿用近两天前旧父 D，
且买价 81,706.10 低于刚确认反弹峰 81,820.85。P1 只证明“止跌反弹有一定
持续时间/幅度”，没有证明大父波段延续或已突破当前反弹链。

## 判断与保持不变

本样本的四次拦截主要是**确认时间延后**，并非证明波段身份错误。
它同时挡住结构较合理的 #90 和指定的 03:17，而较明显混级的 #13 仍通过。
因此不能据此宣布“把 P1 加到 C 就解决了问题”。后续若研究新门槛，还需盈利
C 控制及完整顺序检验；本次没有进行这些操作，也没有挑新参数。

实现脚本 `scripts/audit_btc_c_p1_confirmation.py` 只读取真实数据、保存的六例
和原 P1 低点检查函数；不创建策略、不调用订单、不重放交易。十四波幅独立
复算与五笔原 ledger ATR 逐点一致，03:17 的入场 ATR 也与原记录一致。
只提供入场前已完成 K 线的前缀计算，与提供后来数据但在原时刻截断的结果
逐项相同，确认没有借用后续 K 线。后来的 P1 首过时间单列。

`reports/btc_c_p1_confirmation_2026_11_09/` 保存 `COMPARISON.json`、
`SUMMARY.csv` 和 `PRESERVATION.json`。P1/C 代码、原结果、先前调查、
frozen 0.2、各选择指针、Live Paper 控制及同一 worker 会话保持不变。
